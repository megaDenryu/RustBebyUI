# プロジェクト構造定義 (RustBebyUI)

Bevy の疎結合性を活かし、SengenUI の「View/Orchestrator 分離」の思想を取り入れたディレクトリ構造を定義します。

## 1. ディレクトリ構造

```text
RustBebyUI/
├── _doc/               # プロジェクト仕様・設計書 (Obsidian 管理)
│   ├── 01_コンセプト/
│   ├── 10_実装済み機能仕様/
│   ├── 20_アーキテクチャ・設計/
│   └── 30_実装ガイド・運用メモ/
├── assets/             # フォント、画像、スタイル設定 (TOML/JSON 等)
├── src/
│   ├── main.rs         # エントリポイント (App 構成)
│   ├── app/            # アプリケーション全体のステート・設定
│   ├── components/     # UI/ゲーム要素のタグ、フラグ (ECS Component)
│   ├── ui/             # UI 定義 (View 相当)
│   │   ├── widgets/    # 汎用部品 (ボタン、テキストボックス等)
│   │   └── screens/    # 画面全体のレイアウト
│   ├── systems/        # ロジック・イベントハンドリング (Orchestrator 相当)
│   └── plugins/        # 機能単位でのパッケージング
├── Cargo.toml          # 依存関係定義 (Bevy, UI 拡張 Crate 等)
└── README.md
```

## 2. 各ディレクトリの責務

### `src/ui/` (View 層)
- SengenUI の `View関数` に相当するコードを配置。
- `ui_builder` を用いて、ヒエラルキー構造を構築する責務を持つ。

### `src/systems/` (Orchestrator 層)
- UI 要素（Entity）のイベント（Interaction）を監視し、内部状態の変更やゲームロジックの呼び出しを行う。
- 状態の更新は直接 DOM (Entity) をいじるのではなく、Component を介して行う。

### `src/plugins/`
- 画面単位、あるいは機能単位で `Plugin` トレイトを実装し、`main.rs` での登録を容易にする。
- これにより、開発中のパーツの切り替え（Mock への差し替え等）を容易にする。

## 3. 命名規則
- **日本語命名ポリシー:** `00_コーディング憲法` に則り、コメントや仕様書内、および可能な限りドメインに関わる変数名等には日本語の意図を含める。
- **Rust Standard:** 識別子自体は Rust の慣習（snake_case, PascalCase）に従う。
