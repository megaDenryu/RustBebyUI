# ゲーム設計書: Cyber Studio — マイクラ in VSCode ADV

## 1. コンセプト

ボクセルワールドを歩き回りながら、VSCode風マルチウィンドウUIで情報を集め、
島の因習に巻き込まれた人物を救う（あるいは真相を暴く）アドベンチャーゲーム。

『人のカレンダー』のように現実のWebを探索するARGではなく、
**3Dボクセル空間とゲーム内ウィンドウの両方が調査フィールド**になる。

### 体験の核
1. ボクセルワールドを探索 → 物理的な手がかりを発見
2. ウィンドウ（カレンダー、メッセージ、ドキュメント等）で情報を読み解く
3. 空間 × 時間 × 情報の組み合わせで謎を解く
4. 選択によってストーリーが分岐する

### タイトル候補
- "One O Net - Cyber Studio" (現行タイトルを活用)

## 2. ストーリーエンジン仕様

### 2.1 設計思想: 宣言的ストーリー定義

ストーリーは **Rustの構造体として宣言的に定義** する。
手続き的なスクリプトではなく、データとしてイベントや条件を記述し、
エンジンが評価・発火する。

```rust
// ストーリー定義の例 (Rustコード上で宣言的に書く)
pub fn 第一章イベント群() -> Vec<ストーリーイベント> {
    vec![
        ストーリーイベント {
            識別子: "手紙の発見",
            日付条件: Some(ゲーム日付 { 月: 4, 日: 5 }),
            場所条件: Some(場所条件 {
                座標: Vec3::new(15.0, 6.0, 20.0),
                半径: 3.0,
            }),
            前提フラグ: vec![],
            効果: vec![
                イベント効果::ドキュメント追加("古い手紙".into()),
                イベント効果::通知("足元に古い手紙が落ちている…".into()),
                イベント効果::フラグ設定("手紙発見済み".into()),
            ],
        },
        ストーリーイベント {
            識別子: "村長との会話",
            日付条件: Some(ゲーム日付 { 月: 4, 日: 7 }),
            場所条件: None, // 時間だけで発火
            前提フラグ: vec!["手紙発見済み".into()],
            効果: vec![
                イベント効果::メッセージ追加 {
                    送信者: "村長".into(),
                    本文: "あの手紙のことは忘れなさい。".into(),
                },
                イベント効果::カレンダー追記 {
                    日付: ゲーム日付 { 月: 4, 日: 10 },
                    内容: "祠の清掃（？）".into(),
                },
            ],
        },
    ]
}
```

### 2.2 コアデータ構造

```
ストーリーエンジン
├── ゲーム時間
│   ├── 現在日付 (月, 日)
│   ├── 現在時刻 (時, 分) — 昼夜サイクル連動
│   └── 日送り操作 (睡眠で翌日へ)
│
├── イベントレジストリ
│   ├── Vec<ストーリーイベント> — 全イベント定義
│   └── 評価ループ: 毎フレーム条件チェック → 発火
│
├── フラグストア
│   ├── HashMap<String, bool> — ON/OFFフラグ
│   └── HashMap<String, i32>  — カウンター(任意)
│
├── ドキュメントストア
│   ├── Vec<ドキュメント> — 発見済み文書
│   └── 未読管理
│
├── メッセージストア
│   ├── Vec<メッセージ> — 受信メッセージ
│   └── 会話スレッド管理
│
└── カレンダーストア
    ├── HashMap<ゲーム日付, Vec<予定>> — 日付→予定
    └── 初期予定 + 動的追加
```

### 2.3 イベント効果の種類

| 効果 | 説明 |
|---|---|
| `フラグ設定(名前)` | フラグをONにする |
| `フラグ解除(名前)` | フラグをOFFにする |
| `通知(テキスト)` | 画面に通知を表示 |
| `ドキュメント追加(タイトル)` | ドキュメントウィンドウに文書追加 |
| `メッセージ追加{送信者, 本文}` | メッセージウィンドウに受信 |
| `カレンダー追記{日付, 内容}` | カレンダーに予定追加 |
| `ワールド変更{...}` | ボクセルの設置/破壊、オブジェクト出現 |
| `BGM変更(トラック名)` | 音楽切替 |
| `画面演出(種別)` | 画面フラッシュ、暗転など |

### 2.4 条件の種類

| 条件 | 説明 |
|---|---|
| `日付条件` | 特定の日付（以降/以前/当日） |
| `時刻条件` | 特定の時間帯 |
| `場所条件` | プレイヤーが指定座標の半径内 |
| `フラグ条件` | 指定フラグがON/OFF |
| `アイテム条件` | 特定アイテム所持 |
| `複合条件` | AND/OR で条件を組み合わせ |

## 3. マルチウィンドウUI仕様

### 3.1 ウィンドウ一覧

VSCode風のタブで切り替え可能なウィンドウ群:

| タブ名 | 種別 | 説明 |
|---|---|---|
| **World** | 3Dビュー | ボクセルワールド探索 (既存) |
| **Calendar** | 情報UI | キャラクターの予定表。日付選択でイベント閲覧 |
| **Messages** | 情報UI | キャラクターからの受信メッセージ (チャット風) |
| **Documents** | 情報UI | 発見した手紙・日記・地図などの文書閲覧 |
| **Browser** | 情報UI | ゲーム内偽サイト (将来実装) |
| **Terminal** | 操作UI | コマンド入力・ゲームログ |

### 3.2 サイドバー: 調査ノート

ファイルツリーの代わりに調査の進捗を表示:
- 📋 手がかり一覧 (発見済みフラグのリスト)
- 👤 人物メモ (登場人物と関係性)
- ❓ 未解決の謎

### 3.3 ステータスバー

- 現在日付 (4月5日 etc.)
- 現在時刻 (昼/夕/夜)
- 現在地名
- FPS

## 4. 組み込みHTTPサーバー (将来実装)

ゲームのexeが簡易HTTPサーバーとして動作し、
ブラウザで `localhost:PORT` を開くとゲーム内偽サイトにアクセスできる仕組み。

### 用途
- ゲーム内の「島の公式HP」「学校サイト」「個人ブログ」を実際のブラウザで閲覧
- ゲーム進行に応じてサイト内容が動的に変化
- 現実のブラウザとゲーム内ブラウザウィンドウの連動

### 技術方針
- Rustの軽量HTTPサーバー (`axum` or `warp`) をゲームプロセス内で起動
- ストーリーエンジンのフラグストアを参照してページ内容を動的生成
- `open::that("http://localhost:PORT")` でブラウザ自動起動

## 5. ワールドとストーリーの統合

### 5.1 調査可能オブジェクト

ワールド内の特定座標にインタラクト可能なオブジェクトを配置:
- 看板 → テキスト表示
- 手紙/日記 → ドキュメント追加
- 人物(NPC) → メッセージ/会話
- 祠/特殊建造物 → イベント発火

### 5.2 ワールドの時間連動

ゲーム内日付に応じてワールドが変化:
- 特定の日に新しい建物が出現
- 祭りの日に装飾が追加
- 事件後に道が封鎖される
