# Bevy UI 開発フロー定義

本プロジェクトでは、仕様書駆動開発 (SDD) と Bevy の ECS 構造を融合させた開発フローを採用します。

## 1. 開発フェーズ (SDD ステップ)

### Phase A: 仕様考古学・構想 (WF-100/110)
- **目的:** 何を作るか、どのような UI 体験を提供するかを定義する。
- **成果物:** `01_コンセプト.md` (ワンページャー)

### Phase B: 仕様策定・精錬 (WF-120)
- **目的:** UI コンポーネントの構造、イベントフロー（どのボタンを押すと何が起きるか）を定義する。
- **成果物:** `10_実装済み機能仕様/` 内の仕様書

### Phase C: 実装計画と設計 (WF-200)
- **目的:** Bevy における Entity の設計、使用する Plugin、Component の定義を行う。
- **成果物:** `20_アーキテクチャ・設計/` 内の設計図

### Phase D: 実装実行 (WF-210)
- **目的:** Rust コードを記述し、コンパイル・実行・テストを行う。
- **成果物:** Rust ソースコード (`src/*.rs`)

## 2. Bevy 特化のサイクル

各コンポーネントの実装時は以下の手順を繰り返します。

1.  **Component 定義:** 状態や識別子（ID）を `struct` で定義。
2.  **Plugin 化:** コンポーネントを独立した `Plugin` として作成。
3.  **UI 構築 (Startup System):** `commands` を使って UI ツリーを生成。
4.  **インタラクション (System):** ボタンクリックなどのイベントを処理する System を記述。

## 3. 品質管理

- **Rust 強型チェック:** `cargo check` によるコンパイル時エラー排除。
- **Hot Reloading:** (可能であれば) `bevy_asset_loader` や動的アセット更新を利用して、見た目の調整を高速化。
