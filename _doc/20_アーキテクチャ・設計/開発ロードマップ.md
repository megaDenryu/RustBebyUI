# 開発ロードマップ

## ワークフロー原則

```
[A] ワールド定義 (島の地図)
 ├→ [B] 地形関数の設計 (Aを再現する)
 ├→ [C] ストーリー座標の確定 (Bの出力を使う)
 └→ [D] 描画要件の導出 (Bの範囲から決める)
```

A→B→C,D の順序を守る。下流の変更は上流に遡って整合性を確認する。

---

## Phase 0: 基盤修正

### 目標
起動して地形が見え、全エリアに到達でき、調査ポイントが機能する状態。

### 作業
1. 全エリア/調査ポイントのXZ座標で `地形高さ(x,z)` を実測する
2. ストーリー座標(サンプルストーリー.rs)のY値を実測地形高さに修正する
3. カメラ初期位置を修正後のエリア座標に合わせる
4. 地形Y範囲の実測値からY方向チャンク層数を導出する
5. 総チャンク数からタスク投入数/メッシュ登録速度を設定する
6. フォグ距離を描画距離に合わせる
7. 起動して動作確認

### 成果物
- ストーリー座標の修正コード
- チャンク管理パラメータの確定値と導出根拠の記録

## Phase 1: ワールド定義

### 目標
「瀬戸内海の離島」として成立するワールド。島の形があり、海に囲まれている。

### 作業
1. 島の地図を設計する (エリア配置、高低差、海岸線、XZ範囲)
2. 地形関数を再設計する (島の形状を反映、外周を海面以下にする)
3. 各エリアの座標を地形関数の出力から再確定する
4. サンプルストーリー.rsの全座標を更新する
5. 建造物の配置計画を立てる (祠、民家、学校 -- Phase 5で実装)

### 成果物
- `_doc/20_アーキテクチャ・設計/島の地図設計.md`
- 地形関数の改修コード
- ストーリー座標の更新コード

---

## Phase 2: 描画品質

### 目標
ストーリーの雰囲気を伝える画面。天候・昼夜が正しく機能する。

### 前提
Phase 1 完了

### 作業
1. フォグ色/距離の天候別パラメータを検証・調整する
2. 昼夜サイクル(太陽光の色/角度/照度)を検証・調整する
3. 天候ビジュアル(晴れ/曇り/雨/嵐/霧)の見栄えを検証する
4. 水面の描画を改善する (現状は青いボクセル)
5. 空の色(ClearColor)を時間帯・天候に連動させる

### 成果物
- 天候/昼夜パラメータの調整コード
- スクリーンショットによる各条件の確認記録

---

## Phase 3: インタラクション整備

### 目標
ストーリーを最初から最後まで通しプレイできる。

### 前提
Phase 1 完了

### 作業
1. 衝突判定が全エリアで正しく動作するか検証する
2. 全調査ポイント(4箇所)に到達し、Fキーで調査できるか確認する
3. 全イベントの発火条件(日付/場所/フラグ)を通しで確認する
4. 会話システムの動作確認 (Enter送り、Escスキップ)
5. 選択肢システムの動作確認 (3択の重大選択、エンディング分岐)
6. セーブ/ロードの動作確認 (全ストアの保存・復元)
7. セーブ/ロードの未保存データ修正 (選択肢ストア、会話ストア、エリアストア)

### 成果物
- 全イベント・全ルートの動作確認チェックリスト
- バグ修正コード

## Phase 4: ストーリー品質

### 目標
ゲームとして完成している。3エンディング全ルートが体験として成立する。

### 前提
Phase 3 完了

### 作業
1. 第一章を通しプレイしてテキスト・演出タイミングを調整する
2. 第二章を同様に調整する
3. 第三章 + 3エンディング全ルートを調整する
4. サブイベント(10件)の発火タイミングと内容を確認する
5. テキスト推敲 (不自然な表現、誤字、テンポ)
6. カレンダーの日付とイベントの整合性を最終確認する

### 成果物
- テキスト修正コード
- 全ルートプレイ記録

### 目標

## Phase 依存関係

```
Phase 0 ─→ Phase 1 ─→ Phase 2
                    ├→ Phase 3 ─→ Phase 4
                    │           ├→ Phase 5
                    │           │       │
                    │           └───────→ Phase 6
```

Phase 2 と Phase 3 は Phase 1 完了後に並行可能。
Phase 5 は Phase 3 完了後。
Phase 4 は Phase 3 完了後。
Phase 6 は Phase 4, 5 完了後。

## 考慮事項チェックリスト

各Phaseで以下を確認する:

- [ ] ワールド座標系: 地形関数とストーリー座標が一致しているか
- [ ] 空間設計: エリア間の距離感、島の境界
- [ ] チャンク管理: Y範囲、総数、ロード時間
- [ ] パフォーマンス: フレームレート、初期ロード
- [ ] ストーリー接続: イベント条件の場所判定が地形上で機能するか
- [ ] プレイヤー体験: 到達可能性、操作感、ローディング
- [ ] 仕様書との一致: コードの値と仕様書の記述が合っているか
- [ ] 将来の拡張: 今の設計が後のPhaseを阻害しないか
