# プロジェクト構造定義 (RustBebyUI)

## 1. 現在のディレクトリ構造

```text
RustBebyUI/
├── _doc/                          # プロジェクト仕様・設計書
│   ├── 10_実装済み機能仕様/       # 実装済み機能の仕様
│   ├── 20_アーキテクチャ・設計/   # 設計書・ゲーム設計書
│   ├── 50_仕様検討・提案/         # 検討中の仕様
│   └── 会話履歴/                  # AIとの開発セッション記録
├── assets/                        # フォント等
├── src/
│   ├── main.rs                    # エントリポイント (モジュール宣言・プラグイン登録)
│   │
│   │  -- ドメイン層 (型定義・データ) --
│   ├── ボクセル世界.rs            # ボクセル型・チャンク構造体・定数
│   ├── 四面体世界.rs              # 四面体チャンク構造体・分割定義・隣接テーブル

│   │  -- 描画層 (メッシュ・チャンク管理) --
│   ├── メッシュ生成.rs            # 立方体メッシュの LOD 対応生成
│   ├── 四面体メッシュ生成.rs      # 四面体メッシュ生成 (面カリング付き)
│   ├── チャンク管理.rs            # 立方体チャンクのストリーミング・LOD管理
│   ├── 四面体チャンク管理.rs      # 四面体チャンクのストリーミング
│   │
│   │  -- インタラクション層 (カメラ・物理) --
│   ├── カメラ制御.rs              # 飛行/歩行モード・水中物理
│   ├── 衝突判定.rs                # 7点チェックによる衝突判定
│   │
│   │  -- UI・シーン層 --
│   ├── シーン初期化.rs            # カメラ・ライト・フォグ・マテリアル初期化
│   ├── UI設定.rs                  # サイバーテーマ UI (レイアウト構築・9タブ・サイドバー)
│   │
│   │  -- ストーリーエンジン層 --
│   ├── ストーリーエンジン.rs      # 全データ型定義 (Resource/enum/struct)
│   ├── ストーリー評価.rs          # Bevyシステム関数群 (評価・操作・UI表示更新・天候・昼夜)
│   ├── サンプルストーリー.rs      # ストーリーコンテンツ (全3章・サブイベント・エンディング3分岐)
│   │
│   │  -- 永続化層 --
│   └── セーブ.rs                  # F5セーブ/F9ロード (JSON形式)
│
├── Cargo.toml                     # 依存関係 (bevy, futures-lite, serde, serde_json)
├── CLAUDE.md                      # Claude Code 用プロジェクトガイド
└── run.ps1                        # ビルド・実行スクリプト
```

ソースファイル16個 (main.rs + 15モジュール)、合計約5500行。

## 2. 各層の責務

### ドメイン層
- ボクセルと四面体の型定義・定数・チャンク構造体
- 地形ノイズ生成の共通関数

### 描画層
- メッシュ生成 (LOD対応の立方体・面カリング付き四面体)
- チャンクストリーミング (非同期チャンク生成・距離ベースの読み込み/解放)

### インタラクション層
- カメラ制御 (飛行/歩行モード・水中物理)
- 衝突判定 (7点チェック)

### UI・シーン層
- シーン初期化 (カメラ・ライト・フォグ・マテリアル)
- VSCode風マルチウィンドウUI (9タブ・サイドバー・ステータスバー)
- コンポーネント定義 (タブボタン・ビューコンテナ・マーカー)

### ストーリーエンジン層
- **ストーリーエンジン.rs**: 全データ型定義のみ (Resource・enum・struct)
- **ストーリー評価.rs**: 全Bevyシステム関数 (評価ループ・効果適用・操作処理・UI表示更新・天候ビジュアル・昼夜サイクル)
- **サンプルストーリー.rs**: コンテンツ定義 (イベント・初期データ)

### 永続化層
- セーブ/ロード (全ストアのJSON永続化)

## 3. モジュール解決

Rustの非ASCII識別子は 1.53 以降の安定機能。
日本語ファイル名は `main.rs` の `#[path = "日本語名.rs"]` 属性で解決:

```rust
#[path = "ストーリーエンジン.rs"]
mod ストーリーエンジン;
```

## 4. 命名規則

- **日本語ファイル名**: ソースファイルは日本語名を使用
- **日本語識別子**: struct, enum, fn, const, フィールド名すべて日本語
- **略語禁止**: フルスペルで書く

## 5. 将来のリファクタリング候補

現在は全モジュールが `src/` 直下のフラット構造。
規模が大きくなった場合、以下の階層化を検討:

```text
src/
├── ドメイン/         # ボクセル世界, 四面体世界, 地形生成
├── 描画/             # メッシュ生成, チャンク管理
├── インタラクション/ # カメラ制御, 衝突判定
├── ストーリー/       # エンジン, 評価, コンテンツ
├── UI/               # UI設定, シーン初期化
└── 永続化/           # セーブ
```

また、Bevy Plugin トレイトによる機能分割も検討対象。
現在は `main.rs` で `add_systems` を直接呼び出しているが、
Plugin化すれば機能単位での有効/無効切替が容易になる。
